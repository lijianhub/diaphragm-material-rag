# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

An open-source (MIT), educational RAG project for materials-engineering knowledge retrieval. The initial domain is diaphragm forming with ELGILOY® / HAVAR® Co-Cr-Ni-Mo alloys. Requires Python >= 3.10.

## Commands

```bash
pip install -r requirements.txt               # pytest + pypdf; the only runtime deps today
pytest -q                                     # full suite
pytest tests/test_chunking.py -q              # one file
pytest tests/test_chunking.py::test_name -q   # one test
python scripts/index.py [--store faiss] [--rebuild]   # build/sync the persistent index data/raw -> data/index
python scripts/query.py "How is springback compensated?"   # retrieve + answer from data/index (in-memory fallback)
python scripts/evaluate.py --k 3 --alpha 0.5  # retrieval metrics; writes evaluation/results.jsonl
python scripts/evaluate.py --embedder st:sentence-transformers/all-MiniLM-L6-v2   # real embedding model
python scripts/evaluate_generation.py         # answer metrics and gates, offline extractive answers
python scripts/evaluate_generation.py --llm openai:<model>@low --gate   # LLM answers (cached); exit 1 on a failed gate
python scripts/evaluate_agent.py [--llm openai:<model>@low] [--gate]    # agent benchmark (28 frozen cases, simulated reviewer)
python scripts/evaluate.py --track mlflow --output runs/<name>.jsonl     # record a run (commit first)
python scripts/compare_runs.py               # compare tracked runs; mlflow ui --backend-store-uri sqlite:///mlflow.db
python scripts/serve.py [--port 8000]        # HTTP API (needs data/index; RAG_LLM optional; [api] extra)
cd bff && npm install && npm test && npm run typecheck   # Node.js BFF (Vitest, offline); npm run dev to run on :3000
cd web && npm install && npm test && npm run typecheck && npm run build   # React app (Vitest + jsdom); npm run dev on :5173, ops dashboard on /ops
python experiments/01_naive_rag/run.py        # naive demo: whole documents, no chunking or retrieval
python scripts/agent.py "..." [--llm openai:<model>@low]   # agent run; --pending, --approve <id>, --reject <id> --reason ...
python experiments/10_agentic_rag/run.py     # offline demo of the approval flow (scripted planner)
```

Run `scripts/evaluate.py` before and after any change to chunking, embedding or retrieval, and `scripts/evaluate_generation.py` before and after any change to the prompt or answer handling; report the metric change. It indexes only the tracked samples returned by `evaluation.benchmark_corpus()` (txt, md, html and csv in `data/raw/`; never the private PDF), so scores are reproducible on every clone. Look at the per-category lines as well as the overall score. Never tune defaults (alpha, k1, rrf_k) to maximize the score on this set, because it is also the test set; justify defaults from first principles and use sweeps only as analysis.

There is no linter or formatter configured, and `Makefile`, `docker/` and `config/*.yaml` are currently empty. `README.md` has a capability status table (implemented and tested / tested with fakes only / planned); keep it accurate when a capability changes status, and never mark something implemented that is only designed.

## Import layout

`src/` is the import root, not a package prefix. `pyproject.toml` sets `pythonpath = ["src"]` for pytest and `package-dir = {"" = "src"}` for setuptools, so modules are imported as top-level packages:

```python
from ingestion.loader import load_documents   # correct
from src.ingestion.loader import ...          # wrong
```

Code run outside pytest must add `src/` to the import path itself. Scripts and experiments insert `REPO_ROOT / "src"` into `sys.path` (see `experiments/01_naive_rag/run.py`); for ad-hoc scripts, use `PYTHONPATH=src` or `pip install -e .`.

## Architecture

The pipeline is ingestion → chunking → embedding → retrieval → generation. Each stage is a separate package under `src/`, and the stages are deliberately decoupled: they exchange plain strings and lists rather than shared types. `retrieval/index.py` is the only place that composes them.

- `ingestion/`: `parser.py` holds one parser per format (txt/json, md, html, pdf, docx, xlsx, csv) behind `parse_file()` → `Parsed(sections, metadata)`; DOCX/XLSX are read with `zipfile` + `xml.etree` (no dependency). A `Section` is a citation unit (PDF page, sheet, heading section) with metadata such as `page`, `sheet` or `heading`. `loader.ingest(paths)` returns `IngestResult(documents, failures, skipped, duplicates)` and never stops at a bad file; `load_documents()` is the strict variant that raises. `Document(source, content, metadata, sections)`; empty `sections` means one section equal to `content`. New formats register via `register_parser`. Tests build PDF/DOCX/XLSX files in code with `tests/file_builders.py`; never commit binary fixtures.
- `tokenization.py`: the shared `tokenize()` (lowercase, hyphenated terms kept whole, stopwords removed, optional `stem_tokens`). Embedding and lexical scoring must both use it so they agree on what a term is. `stem()` is a light Porter-style suffix stripper; stems are index keys (`verify` → `verifi`), not words. Query and corpus must use the same stemming setting.
- `chunking/`: `FixedSizeChunker` (character windows with overlap) and `RecursiveChunker` (collapses spaces but keeps line and paragraph breaks, then splits after the last `\n\n`, `\n`, `. ` or ` ` separator). Each chunker returns its own dataclass (`Chunk` / `RecursiveChunk`) with `text, source, start, end`. In `RecursiveChunker`, offsets refer to the normalized text, consecutive chunks never leave gaps, and the overlap always starts on a word boundary.
- `embedding/`: every embedder has `name`, `dim`, `encode`, `encode_many` and optionally `encode_query`. `create_embedder(name)` builds one from a spec: `simple-hash[-dim]` (`SimpleEmbedder`: offline feature hashing, the default and what tests use; word overlap, not meaning), `st:<hf-model>` (`SentenceTransformerEmbedder`, optional `[local-embeddings]` extra), and `bedrock:<model>[@dims]` (`BedrockEmbedder`: Titan Text Embeddings V2, optional `[aws]` extra; one InvokeModel per text with backoff on throttling). An embedder's `name` is itself a valid spec, so `SearchIndex.load` rebuilds the embedder from the manifest. Queries always go through `embedding.query_vector()`, which uses `encode_query`, so asymmetric models get their query prefix. Tests use the fakes in `tests/fakes.py` and never download models or call AWS; the one real-model test needs `RUN_MODEL_TESTS=1`.
- `retrieval/dense.py`: `cosine_similarity` and `dense_search`.
- `retrieval/hybrid.py`: `hybrid_search(query, query_vector, texts, vectors, top_k, alpha)` scores `alpha * cosine + (1 - alpha) * lexical coverage`, both in [0, 1]. The caller embeds the query with the same embedder as the corpus.
- `retrieval/bm25.py`: `BM25(texts, k1, b, stem_tokens)` with Lucene IDF, which is never negative. `.scores(query)` is unbounded.
- `reranking/`: second-stage rerankers with `name` and `score(query, passages) -> List[float]`. `create_reranker(name)` builds `ce:<model>` (`CrossEncoderReranker`, sentence-transformers `CrossEncoder`, `[local-embeddings]` extra) or `bedrock-rerank:<model>` (`BedrockReranker`, bedrock-agent-runtime `rerank` with inline documents, `[aws]` extra). Tests use `FakeCrossEncoder` and `FakeBedrockAgentClient` from `tests/fakes.py`.
- `retrieval/fusion.py`: `reciprocal_rank_fusion(rankings, k=60, weights)` and `rank_by_score`, which drops zero-score items so that "not retrieved" never gets a rank.
- `vectorstore/`: the `VectorStore` interface (`add`, `delete_document`, `search`, `save`, and `load_store`) with `InMemoryVectorStore` (pure Python, exact, the reference) and `FaissVectorStore` (`IndexIDMap2(IndexFlatIP)`, exact; optional `faiss-cpu` dependency, imported lazily). Stores L2-normalize vectors, so scores are cosines. A new backend (OpenSearch, pgvector) must pass the contract tests in `tests/test_vectorstore.py`, which run against every store kind.
- `retrieval/index.py`: `SearchIndex(store="memory"|"faiss")`. Chunking runs per section, and chunks inherit `doc_type`, `title` and the section metadata (offsets are relative to the section). `sync(documents, keep=...)` upserts by SHA-256 content hash and deletes missing sources except those in `keep` (scripts pass files that failed to parse, so they retain their last good version); `save`/`load` write `manifest.json` plus `store/`. `load` refuses an embedder whose `name` differs from the one that built the index. Search asks the store for `dense_candidates` (default 100) neighbours; other chunks get dense score 0. `.search()` returns `SearchResult(text, source, start, end, score, metadata)`. After fusion, `dedupe_overlaps=True` collapses duplicate chunks (same section, overlap ≥ half of the shorter span) into the longest one at the best rank. Neighbouring chunks that share only the overlap border are not duplicates, and treating them as such dropped hit@1 from 0.889 to 0.422. With a `reranker`, the top `rerank_depth` (default 20) candidates are rescored and `score` becomes the reranker score; the first-stage score goes to `metadata["retrieval_score"]`. The manifest stores `rerank_depth`, `dedupe_overlaps` and the reranker name, and `load` rebuilds the reranker unless one is passed in. It ranks by position, so duplicate chunk texts keep their own sources. The lexical side is `lexical="bm25"` (default) or `"coverage"`, with `stem_tokens=True` by default. `fusion="weighted"` (default) max-normalizes BM25 and blends it with cosine by `alpha`; `fusion="rrf"` fuses the two rankings, with `alpha` weighting them (0.5 means equal). BM25 is rebuilt lazily after any change, because IDF depends on the whole corpus.
- `query/`: query transformation on top of `SearchIndex`. `decompose(question)` splits compound questions ("…, and what …") by rule; `expansion_terms(...)` is pseudo-relevance feedback (frequent in the top passages, rare in the corpus, returned as surface words); `LLMQueryRewriter(complete, mode="multi-query"|"hyde")` takes any text-in, text-out function and falls back to the original question if it fails. `retrieve(index, question, transforms=..., prf_terms=...)` runs every query first-stage only (`search(..., rerank=False)`), fuses the rankings (`fusion="rrf"` for paraphrases of one question, which rewards consensus; `"interleave"` for decomposed sub-questions, which needs coverage, because RRF there let a generic chunk found by every sub-query crowd out each part's best match), and reranks against the **original** question. PRF causes query drift on this corpus (hit@1 0.889 → 0.600), so it stays opt-in. LLM multi-query and HyDE (measured with `openai:gpt-5.4-mini@low`) raise hit@3 to 1.000 with MiniLM and retrieve q33, but leave hit@1 unchanged. Never add hand-written synonyms that target known benchmark failures; that is tuning on the test set.
- `evaluation/`: relevance is judged by **evidence phrases** in `evaluation/ground_truth.jsonl` that must appear verbatim in a retrieved chunk, not by chunk ids, so the ground truth survives chunking changes. The metrics are hit@k, recall@k (over evidence phrases) and MRR, overall and per question `category` (`keyword`, `paraphrase`, `distractor`, `multi`). `tests/test_evaluation.py` checks that every evidence phrase exists in the corpus; when you edit the samples or questions, keep them in sync. When the benchmark saturates, expand it and freeze it **before** implementing the method it will judge, and record results in `docs/11-rag-evaluation.md`. `evaluation/generation.py` scores **answers** on `evaluation/generation_cases.jsonl` (71 cases: the 45 retrieval questions as `answerable` with `key_facts`, plus `unanswerable`, `ambiguous` and `malicious`); scoring is rule-based and offline (key facts with alternative phrasings, citations that hold the evidence, clean refusals, forbidden output), and `GATES` are thresholds fixed before the first measurement. The evaluator's own refusal detector is deliberately separate from the pipeline's guard, so a bug in one does not hide itself. Report generation errors separately from retrieval misses (`evidence_offered`). Results are in `docs/11-rag-evaluation.md`. `evaluation/agent.py` scores **agent runs** on `evaluation/agent_cases.jsonl` (28 cases: answer, lookup, action, no_action, unanswerable, injection, rejection), frozen in `03b538e` before any run was scored; `evaluate_agent()` gives every case a fresh agent with a fixed run ID (so `CachedLLM.tool_turn` makes reruns free) and answers approvals with `simulated_review` (the case's decision for the requested lot, else reject). Any attempt to call the action tool counts as an action, even an invalid one. A retry needs a rejection first. Safety gates are zero tolerance; quality gates 0.8. The refusal detector misses "I couldn't find … in the available sources" (u-02); widen it only together with new generation cases and a re-run of both benchmarks, never to pass a measured run.
- `api/`: `create_app(settings, index=, llm=, metrics=)` builds the FastAPI app (tests inject an index and `FakeLLM`; tests skip without FastAPI). `POST /ask` (sync handler: the pipeline blocks), `/health` (liveness), `/ready` (503 until an index loads), `/metrics` (Prometheus text from the in-house `api/metrics.py`; label values come only from route templates and fixed outcomes, never user input). Every response carries `X-Request-ID` (the caller's if it matches `[A-Za-z0-9._:-]{1,64}`, else a UUID); every request logs one JSON line to the `rag.api` logger with stage timings, model, prompt version and tokens, but **never the question text** (length and a 12-character SHA-256 only). Unexpected errors return `500 internal_error` without internals. `Settings.from_env()` reads `RAG_INDEX_DIR`, `RAG_LLM`, `RAG_LLM_TIMEOUT` (30 s) and `RAG_LLM_MAX_RETRIES` (1); a configured LLM that cannot be built fails at startup. `RAGPipeline` answers carry `timings` (retrieval_ms, generation_ms). `POST /ask/stream` streams SSE events `sources`, `delta`, `final` (same body as `/ask`, authoritative: the client replaces the deltas with it) or `error`, built on `RAGPipeline.stream()` (shares `_finish()` with `answer()`) and the backends' `stream_chat()`. It is served through `ClosingStreamingResponse(closing_stream(...))`: with Uvicorn (ASGI 2.4) Starlette does not watch for disconnects, and without these the generator was abandoned on disconnect and the LLM kept generating; `test_a_client_disconnect_closes_the_llm_stream_on_a_real_server` uses a real Uvicorn server because closing generators directly in unit tests missed this. Load-test with one pooled HTTP client: creating a client per request costs ~200 ms and once made a 2 ms service look like 690 ms. Details and measurements in `docs/14-production-rag.md`. Read-only `/ops/summary|feedback|evaluations|ingestion` serve the ops dashboard: `Metrics.snapshot()` counts traffic only on `TRAFFIC_ROUTES` (health checks and dashboard polls would inflate it) and estimates percentiles with `Histogram.quantile` (Prometheus-style interpolation; buckets start at 1 ms, because a 5 ms first bound made every 2 ms request read p95 = 4.8 ms); `api/ops.py` reads `logs/feedback.jsonl` and `runs/runs.jsonl` (`RAG_RUNS_PATH`, written by `--track jsonl`), skipping damaged lines, and gives each run a `data_version` (hash of its `data.*` tags); runs with different data versions are never joined in a trend. `scripts/index.py` writes `ingest_report.json` next to the index (`ingestion/report.py`, repository-relative paths). Details in `docs/18-ops-dashboard.md`.
- `bff/` (Node.js 22+, TypeScript, ESM, Fastify 5): `buildApp(config)` in `src/app.ts`, config from env in `src/config.ts` (`RAG_API_URL`, `BFF_API_KEYS` empty = auth off, `BFF_RATE_LIMIT_MAX`, `BFF_CORS_ORIGINS`, `BFF_UPSTREAM_TIMEOUT_MS`). Routes `/api/ask`, `/api/feedback`, `/api/ops/*` (GET, `authenticateAdmin` with `BFF_ADMIN_KEYS`: a user key gets 403, and with only user keys configured ops is closed; all via `proxyJson`), `/api/ask/stream` (raw SSE pass-through after `reply.hijack()`; aborts the upstream fetch on client `close`), `/api/health`, `/api/ready`. Keep `requestIdHeader: false`: otherwise Fastify uses the caller's header as-is and skips the `genReqId` whitelist. Fastify strips unknown body fields by default (`removeAdditional`); a test pins it. Tests (`test/app.test.ts`, Vitest) use an in-process `node:http` fake upstream and never need Python; the disconnect test listens on a real port. Node's built-in `fetch` pools connections; never create an HTTP client per request. Details in `docs/16-backend-for-frontend.md`.
- `web/` (React 19, Vite, Tailwind 4, TypeScript with `erasableSyntaxOnly`, so no constructor parameter properties): `src/lib/sse.ts` (`SSEParser`, incremental; `EventSource` cannot POST), `src/lib/api.ts` (`streamAnswer` with `TextDecoder` stream mode, `sendFeedback`, `ApiError` with request ID), `src/lib/citations.ts` (`splitCitations`; only numbers in `citations` become links), components in `src/components/`; the ops dashboard is `src/ops/` (lazy chunk, routed by `Root.tsx` on `/ops`; admin key in memory only; rates from counter snapshots, restart-safe, in `series.ts`; hand-written single-series SVG `LineChart` with tooltip and a table beside it; `refreshMs` prop so tests use real timers, because fake timers stalled the pending `json()` work). The `final` event replaces the streamed text. Vite proxies `/api` to the BFF (`BFF_URL`). Tests stub `fetch` with `ReadableStream` bodies from `src/test/fixtures.ts`; never call a real server. oxlint flags `setState` in effects; adjust state during render instead. The API's `POST /feedback` appends to `logs/feedback.jsonl` (`RAG_FEEDBACK_PATH`) and counts `rag_feedback_total{rating}`; the comment is never logged. Details in `docs/17-web-app.md`.
- `agent/` (`docs/13-agentic-rag.md`): a plain-Python state machine (`running → awaiting_approval → deciding → completed|stopped|failed`). `Agent(planner, tools, store, limits, on_event)`: `start(question)`, `decide(run_id, approve|reject, reviewer, reason)`. Planners return `generation.llm.ToolTurn`: `LLMPlanner(llm)` uses the backends' native tool calling (`tool_turn(system, transcript, tools)` on `OpenAILLM` and `AnthropicLLM`; the transcript is provider-neutral and JSON-able; provider items, including reasoning and thinking blocks, are replayed unchanged), and `RulePlanner` is offline (search, alloy lookup, extractive answer; never a side effect). `Tool(name, description, parameters, func, side_effect, timeout_s)`; arguments are validated in code by `tools.validate` (`strict` off), unknown tools, non-JSON arguments and repeated calls are answered with errors, tools run in a thread pool with a timeout, results are escaped and capped. A `side_effect` tool is never run by the loop: the run pauses with `pending`, is stored in SQLite (`RunStore`, `claim()` is a compare-and-set so one decision wins), and the tool runs on approval with idempotency key `run_id:call_id` (`NcrStore`). Limits: 6 turns, 12 tool calls, 40,000 tokens, 90 s of active time (approval wait excluded). Every call gets a result entry (both APIs require it); calls after a pending one in the same turn get "not run". The final answer goes through `strip_refusal_citations` and `check_citations`; the agent prompt must keep the guard's wording "not in the sources". The API builds the agent lazily (no database file until first use); the BFF sets `reviewer` from the admin key. Tests use `FakePlanner` and `FakeToolClient` from `tests/fakes.py`.
- `tracking/`: `RunRecord(name, params, metrics, tags, artifacts)` and trackers behind one `log_run()` interface: `NullTracker` (default), `JsonlTracker` (`runs/runs.jsonl`, no dependencies) and `MlflowTracker` (optional `[tracking]` extra, lazy import; tests use `FakeMlflow`, and the real round trip needs `RUN_MLFLOW_TESTS=1`). `create_tracker(kind, repo_root)` pins `mlflow.db`, `mlartifacts/` and `runs/` to the repository root (all git-ignored) unless `MLFLOW_TRACKING_URI` is set. `version_tags()` records `git_commit`, `git_dirty`, SHA-256 of each evaluation file and a corpus fingerprint. `log_safely()` turns tracking errors into a warning: tracking must never fail an evaluation. Commit before a tracked run and write its results to the git-ignored `runs/`, so every run points to a clean commit; compare only runs with the same data hashes. Details in `docs/15-experiment-tracking.md`.
- `generation/`: `prompt.py` builds grounded prompts: `build_prompt(question, results, max_context_tokens)` → `Prompt(system, user, included)` with numbered `<source id="n" label="…">` blocks in rank order, `<`/`>` escaped in the sources **and the question** against prompt injection, and a ~4-chars-per-token budget (the first source is truncated rather than dropped). It also provides `citation_label`, `parse_citations` and `check_citations`. `rag_chain.py`: `RAGPipeline(index, complete=None, top_k, retrieve_fn=None).answer(question)` → `Answer(text, citations, sources, used_llm, invalid_citations, fallback_reason, prompt)`. `complete` is any text-in, text-out LLM function; without one, or when it raises, `ExtractiveAnswerer` quotes matching sentences with citations. It cannot judge answerability ("price of titanium" quotes "titanium nitride"), which is a known limitation for the LLM step and generation evaluation to address. With nothing retrieved, no LLM call is made. `answer(question, documents=[...])` accepts plain passages for quick experiments. `llm.py`: `OpenAILLM` (Responses API; `instructions` + `input`; no default model ID, no sampling parameters; refusal or `content_filter` → `LLMRefusal`) and `AnthropicLLM` (default `claude-opus-5-5`, explicit `effort`, no sampling parameters, server-side refusal fallback, text blocks only, `last_call` with the served model and token usage; `chat(system, user)` is preferred by the pipeline) and `create_llm("anthropic:<id>" | "openai:<id>")`, optional `[llm]` extra. Every `Answer` records `model`, `prompt_version` (`PROMPT_LABEL` plus a SHA-256 fingerprint of `SYSTEM_PROMPT`; bump the label on intentional edits) and `usage`. Credentials only come from the environment (`OPENAI_API_KEY`, `ANTHROPIC_API_KEY`) or the git-ignored `.env`, which `config.load_env_file()` loads at script startup without overriding real variables and without printing values; `RAG_LLM` selects the default model. Never write a key into code, docs, tests or `.env.example`. `scripts/check_llm.py` verifies the setup. Cost control: the `@effort` spec suffix (`openai:<model>@low`), and `CachedLLM` (an on-disk JSONL cache in the git-ignored `.cache/`, keyed by model name, system and user, so evaluation reruns are free; it never caches errors). The user asked to save tokens: use a small model, low effort, the cache, and a single `check_llm.py --ping` before any batch, and report token counts. Tests use `FakeAnthropicClient` and `FakeOpenAIClient`; the real-API test needs `RUN_LLM_TESTS=1`. `strip_refusal_citations()` removes citations from sentences saying the sources lack the answer (including citations after the full stop), enforced in code rather than trusted to the prompt; `Answer.refused` is true when every sentence declines. The current prompt is `grounded-v2` (adds the no-citation refusal and ambiguity rules).

## Conventions

- Optional heavy dependencies (`faiss-cpu`, `sentence-transformers`, `boto3`, `anthropic`) are imported lazily inside the backend that needs them, declared under `[project.optional-dependencies]`, and their tests are skipped when missing. The core install and test suite must work without them.

- Every module starts with `from __future__ import annotations` and uses `@dataclass` for records with `typing` hints.
- Tests and the default demo must run offline, with no network or API keys. This is why the embedder is deterministic. Real model or API backends should be added alongside the offline implementation, not replace it. Test-specific rules are in `.claude/rules/testing.md`.
- `data/raw/Elgiloy_Havar_Material_Requirements_for_Diaphragm.pdf` is git-ignored and must not be committed. Only redistributable sample text belongs in `data/raw/`.
